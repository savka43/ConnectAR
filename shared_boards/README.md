# shared_boards — общий источник истины

Размеченные данные плат, которые используют все клиенты (`ios/`, `android/`, `web/`). Правки содержимого (опрос, шаги, тексты, разъёмы, кабели, разметка) делаются **только здесь**; клиенты их не дублируют вручную.

```
shared_boards/
├── index.json                  # список поддерживаемых плат
├── schema/board.schema.json    # JSON Schema формата платы (schemaVersion 3)
├── scripts/validate.mjs        # проверка данных и эталонная реализация плана (Node ≥ 18, без зависимостей)
├── fixtures/layout-cases.json  # BoardLayout: входы и ожидаемые координаты — для тестов всех клиентов
├── fixtures/plan-cases.json    # план сборки: мини-плата, ответы опроса, ожидаемые шаги — для тестов всех клиентов
└── boards/<board-id>/
    ├── board.json              # опрос, этапы, разъёмы, кабели, шаги сборки
    └── target.jpg              # (опционально) эталон для image tracking
```

## Формат `board.json`

- `physical` — реальный размер платы в мм (`widthMm`, `heightMm`); задаёт масштаб для AR.
- `target.image` — эталонное фото: строго сверху, без бликов, обрезано точно по краю платы, задняя I/O-панель слева; пропорции совпадают с `physical` (±3 %). Без `target` AR для платы недоступен, клиенты открывают фото-режим.
- `setup` — опрос «Ваша сборка»: вопросы с вариантами (`options`) и ответом по умолчанию (`default`). Ответ — `id` варианта.
- `phases` — этапы сборки в порядке выполнения; группируют шаги в чек-листе.
- `connectors` — разъёмы на плате: `name` как на шелкографии, `hint` — короткое уточнение для метки («2-й от CPU»), `rectMm` — прямоугольник в мм от левого верхнего угла платы (`x`, `y` — левый верхний угол разъёма).
- `pools` — наборы разъёмов, которые повторяющиеся шаги занимают по очереди (порты SATA).
- `cables` — кабели: `deviceSide` — куда подключается на плате или устройстве, `psuSide` — где он у блока питания (блок «Со стороны блока питания»), `warning`; `variants` переопределяют `psuSide`/`warning` по ответам опроса (тип БП).
- `steps` — шаги в порядке выполнения: `phaseId`, `title`, `instruction`, `substeps` (короткие действия), `warning`, `connectorIds` (что подсвечивать), `cableIds`, `manualPage` (печатная страница руководства), `icons.{ios,android,web}`, а также `when`, `repeat`, `pool`, `variants` — см. ниже.

Все `id` — kebab-case, уникальны в пределах своего списка.

## План сборки

Клиенты строят из `board.json` и ответов опроса **план** — список конкретных шагов. Правила одинаковые во всех клиентах; эталонная реализация — `resolvePlan` в `scripts/validate.mjs`, общие тесты — `fixtures/plan-cases.json`.

1. **Ответы.** Неизвестный вопрос игнорируется; отсутствующий или неизвестный ответ заменяется `default`.
2. **Условие.** `when` — `{ "id вопроса": ["допустимые ответы"] }`; шаг входит в план, если совпали все вопросы. Без `when` шаг входит всегда.
3. **Вариант.** Первый вариант из `variants`, у которого выполнено `when`, переопределяет заданные в нём поля: `title`, `connectorIds`, `cableIds`, `instruction`, `substeps`, `warning`. Остальные поля берутся из шага.
4. **Повтор.** `repeat` — id вопроса с вариантами-числами; шаг повторяется столько раз (0 — шаг пропускается). Id повтора — `<id>-<n>`, в текстах `{n}` заменяется номером.
5. **Пул.** Каждый экземпляр шага с `pool` занимает следующий свободный разъём пула (в порядке шагов) и добавляет его в конец `connectorIds`; `{port}` в текстах заменяется его `name`. Валидатор проверяет, что разъёмов в пуле хватает на максимальные ответы.
6. **Состояния.** Текущий шаг — первый невыполненный шаг плана. Прогресс хранится по id шагов плана; при смене ответов выполненные шаги, которых больше нет в плане, просто не показываются.

## Добавить плату

1. Создать `boards/<board-id>/board.json` по схеме.
2. Добавить `<board-id>` в `index.json`.
3. Снять `rectMm` разъёмов линейкой с платы. Для AR положить `target.jpg` и указать `"target": { "image": "target.jpg" }`; `targets.mind` для web компилируется в CI (`web/scripts/compile-targets.mjs`).
4. `node shared_boards/scripts/validate.mjs`.

## Требует проверки на живой плате

Координаты сняты с `target.jpg` (Gigabyte B450 AORUS M). Угловые порты SATA стоят парами друг над другом, поэтому два номера делят один прямоугольник. По шелкографии у разъёмов и схеме на стр. 15 руководства: нижний на фото блок — `sata3-0`/`sata3-1`, верхний — `sata3-2`/`sata3-3`; у вертикальной пары нижний разъём — `asata3-0`, верхний — `asata3-1`. Какой номер в блоке верхний порт, а какой нижний, по фото сверху не видно — это и разбивку по блокам нужно сверить с подписями на живой плате. Пока в метках этих портов подсказка «сверьте подпись у разъёма».
