# iOS: опрос и полный чек-лист — план

Web уже работает по `board.json` v3: сначала опрос «Ваша сборка», потом чек-лист полной сборки по этапам. iOS пока показывает старые 5 шагов из `DemoAssembly.swift`. Переводим iOS на те же данные и тот же сценарий. Как должно себя вести — смотрим в web: `web/src/plan.js`, `session.js`, `app.js`. Правила плана описаны в [`shared_boards/README.md`](../shared_boards/README.md#план-сборки), общая картина — в [дизайне, раздел 6](design-doc.md#6-опрос-и-полный-чек-лист).

## 1. Данные из `shared_boards`

- Удалить `Data/DemoAssembly.swift`.
- Добавить `../shared_boards` в проект ссылкой на папку (синяя папка, без копирования, target ConnectAR). Тогда плата лежит в бандле по пути `shared_boards/boards/<id>/board.json`.
- `Data/BoardRepository.swift` читает и декодирует `board.json`. Если не получилось, приложение не падает, а показывает экран «Не удалось загрузить данные платы» с текстом ошибки.

## 2. Модели под схему v3

В `Models/AssemblyModels.swift` заменить `PCComponent` / `BoardConnector` / `AssemblyStep` на `Codable`-модели по `shared_boards/schema/board.schema.json`. На чём легко споткнуться:

- `default` и `repeat` — ключевые слова Swift, нужны `CodingKeys`;
- `when` — это `[String: [String]]` (id вопроса → подходящие ответы);
- у шага почти всё необязательно: `connectorIds`, `cableIds`, `substeps`, `warning`, `manualPage`, `variants`, `pool`, `repeat`, `when`; у кабеля — `psuSide` и `variants`;
- иконка шага — `icons.ios`, если её нет — `wrench.and.screwdriver`.

## 3. Построение плана

`Models/AssemblyPlanner.swift` — чистая функция «плата + ответы → шаги», делает то же, что `resolvePlan` в web:

1. Незнакомые ответы и пропуски заменяются на `default`.
2. Шаг берётся, если подходит его `when`.
3. Первый подходящий `variant` подменяет текст, разъёмы и кабели.
4. `repeat` — шаг повторяется по числу из ответа: id `<id>-<n>`, `{n}` → номер.
5. `pool` — каждый повтор берёт следующий свободный разъём пула (SATA): `{port}` → его имя.

Там же кабель под ответы: `psuSide` и `warning` берутся из подходящего варианта (тип БП).

## 4. Сессия

`App/AssemblySession.swift` хранит ответы, флаг «опрос пройден», план, выполненные шаги и заметки. Ключ в `UserDefaults` — `assembly.v2.<boardId>`.

- Сменили ответ — план сразу пересобирается. Пока опрос не пройден, ответы не сохраняются.
- Текущий шаг — первый невыполненный в плане. Прогресс считается только по шагам плана.
- Если шаг выпал из плана после смены ответов, его отметка не теряется, просто не учитывается. Вернули ответ — отметка снова на месте.
- Сброс прогресса не трогает заметки. Битое сохранение → чистое состояние, без падения.
- Переезд со старой версии: если есть только `assembly.v1.<id>`, забираем отметки и заметки шагов `ram`, `gpu`, `atx`, `cpu-power` (у них id не поменялся). Опрос пользователь проходит заново.

## 5. Экраны

- **Опрос** (`Features/Setup/SetupView.swift`, новый). При первом запуске открывается шторкой, которую нельзя смахнуть, внизу кнопка «Построить чек-лист». Вопросы берутся из `setup`. Где варианты короткие — сегменты, тип БП — меню. Видно, сколько шагов получится. Потом опрос открывается с главной и из чек-листа, изменения применяются сразу.
- **Главная.** Текущий шаг (иконка, название, разъёмы или «Без разметки на плате»), строка с ответами опроса, «Выполнено X из Y». Убрать фразу про уже установленные процессор и охлаждение.
- **Чек-лист.** Шаги по этапам из `phases`, в заголовке этапа — «3/4». Пустые этапы не показываем. `BuildConfigurationView` удаляется, вместо него «Изменить сборку».
- **Подсказки.** Шаги плана по этапам, поиск по названию шага и имени разъёма. Кнопка «Добавить в мою сборку» больше не нужна.
- **Карточка шага.** Иконка, название, пометка «Текущий шаг». «На плате: DDR4_2 (2-й от CPU), DDR4_1 (4-й от CPU)» или «Этот шаг без разметки на плате». Затем инструкция, «Как сделать» нумерованным списком, предупреждение (выделено). Для каждого кабеля — куда подключается, «Со стороны блока питания» и его предупреждение. Ссылка на руководство — только если есть `manualPage`. Заметка и отметка — как сейчас.
- **Камера (фото-режим).** В выборе для ручной метки — шаги плана, по умолчанию текущий. У шага с несколькими разъёмами видны все имена, у шага без разъёмов — «Шаг без разметки на плате».

Доступность: Dynamic Type, подписи VoiceOver у отметки шага («Выполнено» / «Не выполнено»), тёмная тема, поворот экрана.

## 6. Тесты

`scripts/test-session.sh` собирает через `swiftc` модели, планировщик, `BoardRepository`, сессию и тесты, данные читает из `../shared_boards`. Поэтому модели, план и сессию пишем без SwiftUI, только Foundation и Combine. Проверяем:

- все кейсы `shared_boards/fixtures/plan-cases.json`: шаги и кабели совпадают с ожидаемыми;
- реальную плату:
  - память: 1 модуль → `ddr4-1`; 2 → `ddr4-2, ddr4-1`; 4 → все четыре слота;
  - накопители: 2 SATA SSD + 1 HDD → `sata-ssd-1`, `sata-ssd-2`, `hdd-1` на `sata3-0/1/2`;
  - без видеокарты — `display-igpu` вместо `gpu`;
  - модульный БП меняет текст у `atx24`;
  - у всех подсвечиваемых разъёмов есть `rectMm`;
- сессию:
  - первый запуск идёт без опроса;
  - ответ пересобирает план и не сохраняется до конца опроса;
  - после перезапуска всё на месте;
  - шаги вне плана;
  - сброс оставляет заметки;
  - переезд с v1;
  - битое хранилище;
  - две платы не мешают друг другу.

`ios.yml` уже срабатывает на изменения в `shared_boards/**`, отдельно настраивать не нужно.

## Не сейчас

AR в iOS. Когда до него дойдёт, логику меток берём из web (`markers.js`, `camera.js`): подсвечиваем разъёмы шагов плана, у текущего шага к метке добавляется `hint`, для шага без разъёмов — плашка «Сейчас: …».

## Готово, когда

- `DemoAssembly.swift` нет, данные берутся из `shared_boards` в бандле;
- первый запуск: опрос → чек-лист по этапам;
- одинаковые ответы дают одинаковый список шагов в iOS и web;
- в карточке шага есть «Как сделать», предупреждение и «Со стороны блока питания» под выбранный БП;
- прогресс и заметки старой версии не потерялись;
- проходят `sh scripts/test-session.sh` и сборка в `ios.yml`.
