# AR-распознавание платы — дизайн

Дата: 2026-10-05 · Статус: согласован

## Цель

Пользователь наводит камеру на материнскую плату, приложение распознаёт её и показывает поверх реальной платы разъёмы из сценария сборки. Тап по разъёму открывает инструкцию, прогресс чек-листа отражается на подсветке. Работает в трёх клиентах — iOS, Android и web — на общих данных из `shared_boards/`.

Первая плата: **Gigabyte B450 AORUS M (rev. 1.x)**, физический экземпляр есть у команды.

## Решения

| Вопрос | Решение |
|---|---|
| Способ привязки к плате | Image tracking по эталонному фото (ARKit / ARCore Augmented Images / MindAR) |
| Что показываем | Все разъёмы выбранных компонентов; следующий невыполненный шаг подсвечен ярче, выполненные приглушены |
| Место в приложении | Вкладка «Камера» открывается в AR; фото-режим остаётся запасным |
| Заморозка кадра | Есть во всех клиентах; основа — обобщённый фото-режим |
| Единицы координат | Миллиметры |
| Отвергнуто | Ручная калибровка по углам (не распознавание; можно добавить позже как страховку), ML-распознавание через Vision/Create ML (нужен датасет — избыточно для MVP) |

## 1. Контракт данных (`shared_boards`, schemaVersion 2)

```json
{
  "schemaVersion": 2,
  "physical": { "widthMm": 244, "heightMm": 244 },
  "target": { "image": "target.jpg" },
  "connectors": [
    { "id": "atx", "name": "ATX", "componentId": "psu-atx",
      "rectMm": { "x": 210, "y": 78, "w": 12, "h": 58 } }
  ]
}
```

Значения `rectMm` в примере условные — реальные снимаются линейкой с платы.

- **`target.jpg`** — фото платы строго сверху, без бликов, обрезанное точно по краю платы, в ориентации схемы из руководства (задняя I/O-панель слева).
- **`rectMm`** — прямоугольник разъёма в мм; начало координат — левый верхний угол платы; `x`, `y` — левый верхний угол разъёма.
- **`physical`** — реальный размер платы; задаёт масштаб для AR-движка.

### Перевод в координаты якоря

Смещение центра разъёма от центра платы:

```
dx = x + w/2 − W/2
dz = y + h/2 − H/2
```

| Клиент | Система координат якоря | Позиция |
|---|---|---|
| iOS — `ARImageAnchor` | центр фото, плоскость XZ, метры | `(dx/1000, 0, dz/1000)` |
| Android — `AugmentedImage` | центр фото, плоскость XZ, метры | `(dx/1000, 0, dz/1000)` |
| Web — MindAR anchor | центр, плоскость XY, ширина цели = 1 | `(dx/W, −dz/W, 0)` |

Углы прямоугольника считаются той же формулой для `(x, y)`, `(x+w, y)`, `(x+w, y+h)`, `(x, y+h)`.

## 2. Архитектура клиентов

Каждый клиент состоит из четырёх частей:

| Часть | Ответственность | iOS | Android | Web |
|---|---|---|---|---|
| **Tracker** | Найти плату, выдать якорь и состояние | ARKit + RealityKit; `ARReferenceImage` строится в рантайме из `target.jpg` | ARCore; `AugmentedImageDatabase.addImage` в рантайме | MindAR; `targets.mind` компилируется в CI |
| **BoardLayout** | `rectMm` → локальные координаты якоря | чистая функция | чистая функция | чистая функция |
| **Highlight** | Полупрозрачный прямоугольник, лежащий на разъёме (3D) | `ModelEntity` с plane mesh | нода с plane | mesh three.js |
| **Labels** | Метки-кнопки поверх камеры (2D), позиция = проекция центра разъёма каждый кадр | SwiftUI + `ARView.project` | Compose + проекция | HTML + `Vector3.project` |

Метки двумерные: всегда читаемы, удобно тапать, поддерживают крупный шрифт и выглядят так же, как в фото-режиме.

**Состояние метки** берётся из существующей сессии сборки: `current` — первый невыполненный шаг среди выбранных компонентов, `done` — выполненные, `pending` — остальные. Разъёмы невыбранных компонентов не показываются.

## 3. Поток данных

1. **Загрузка.** iOS — `shared_boards` в бандле; Android — `shared_boards` как дополнительная папка assets в Gradle; web — JSON и `targets.mind` в сборке.
2. **Открытие «Камеры».** Проверка поддержки AR (`ARWorldTrackingConfiguration.isSupported` / `ArCoreApk.checkAvailability` / камера + WebGL) → эталон из `target.jpg` и `physical.widthMm` → запуск сессии.
3. **Состояния трекинга** (одинаковые во всех клиентах):

   | Состояние | Когда | Подсказка |
   |---|---|---|
   | `searching` | плата не найдена | «Наведите камеру так, чтобы плата целиком попала в кадр» |
   | `tracking` | якорь есть | — (показаны метки) |
   | `limited` | трекинг потерян | «Плата потеряна — наведите камеру снова»; метки скрыты |

4. **Плата найдена** — один раз создаются подсветки и метки; дальше каждый кадр обновляются только экранные позиции меток. Метки за пределами экрана или за камерой скрываются.
5. **Тап по метке** — существующий экран инструкции для шага.
6. **Шаг отмечен** (в инструкции или чек-листе) — сессия обновляется, AR-вью перекрашивает подсветки без перезапуска трекинга.
7. **Уход с вкладки** — пауза сессии; возврат — продолжение, при потере якоря — `searching`.

### Заморозка кадра

В состоянии `tracking` доступна кнопка «Заморозить»:

1. Снимается кадр камеры без 3D-подсветки (iOS — `ARView.snapshot` со скрытой подсветкой; Android — `PixelCopy`; web — `<video>` на canvas с той же обрезкой, что на экране).
2. Четыре угла каждого `rectMm` проецируются на экран → четырёхугольники в перспективе.
3. Снимок и метки (центр + полигон) передаются в **`BoardPhotoView(image, markers)`** — обобщённый фото-режим: в ручном режиме метки ставит пользователь, в замороженном они приходят из AR. Зум, тапы, переход к инструкции и подсветка текущего шага реализованы один раз.

«Вернуться в AR» возвращает живую камеру. Снимок хранится только в памяти сеанса. Если плата не находится (например, видеокарта уже закрывает её), пользователь замораживает кадр заранее или переходит в ручной фото-режим.

## 4. Обработка ошибок

Принцип: любая ошибка ведёт в ручной фото-режим, тупиков нет.

| Ситуация | Поведение |
|---|---|
| Нет доступа к камере | Объяснение + «Открыть настройки» (web — текстовая инструкция) + «Выбрать фото из галереи» |
| AR не поддерживается | Сразу фото-режим с пометкой. Android — сначала предложить установить ARCore (`ArCoreApk.requestInstall`). Web во встроенном браузере — совет открыть в Safari / Chrome |
| Битые данные платы | AR для платы недоступен → фото-режим, без падения; запись в лог. Основная защита — CI |
| Эталон отклонён движком | iOS `ARReferenceImage.validate`, Android `ImageInsufficientQualityException`, web — ошибка загрузки `.mind` с «Повторить» → как битые данные |
| Долгий поиск | ~10 с — советы (свет, расстояние, плата целиком, «Поддерживается Gigabyte B450 AORUS M»); ~25 с — крупная кнопка «Перейти в режим фото» |
| Трекинг потерян | Метки скрыты, «Заморозить» неактивна, подсказка |
| Прерывание (звонок, сворачивание) | Пауза и продолжение; iOS `sessionWasInterrupted`, Android `onPause`/`onResume`, web `visibilitychange` |
| Ошибка заморозки | Тост «Не удалось сохранить кадр», остаёмся в AR |
| Web: долгая загрузка | Экран загрузки с прогрессом (TF.js, `.mind`) |

## 5. Тестирование

1. **Данные — `shared-boards.yml`.** `validate.mjs` для схемы v2: наличие `physical` и `rectMm`; `target.jpg` существует и его пропорции совпадают с `physical` (±3 %); `rectMm` внутри платы; у каждого шага есть разъём с `rectMm`; корректность `fixtures/layout-cases.json`.
2. **Общая математика.** `shared_boards/fixtures/layout-cases.json` — входы и ожидаемые выходы (смещение в метрах, 4 угла, web-координаты). Прогоняется в каждом клиенте: XCTest (`ios.yml`), JUnit (новый `android.yml`, Gradle `test` на ubuntu), Vitest (`web.yml`, до деплоя).
3. **Логика меток** (юнит-тесты на каждой платформе): `current` / `done` / `pending`, скрытие невыбранных, point-in-polygon для замороженных меток, сдвиг текущего шага после отметки.
4. **Качество эталона** (вручную при замене `target.jpg`): `arcoreimg eval-img` ≥ 75 через `shared_boards/scripts/check-target.sh`; отсутствие предупреждений Xcode; успешная компиляция `.mind` в `web.yml`.
5. **Ручная проверка на плате:** распознавание с 30–60 см, под углом до ~45°, при лампе и дневном свете; приближение вплотную к ATX после распознавания; установка видеокарты после распознавания; заморозка → зум → тап → инструкция → отметка шага; запрет камеры, прерывание, долгий поиск; web в Safari (iOS), Chrome (Android), встроенном браузере Telegram.

### Критерии готовности MVP

- Плата распознаётся за ≤ 3 с при нормальном освещении.
- Подсветка совпадает с разъёмом с точностью ~5 мм на расстоянии 40 см.
- Тап открывает инструкцию; отметка шага перемещает подсветку.
- Заморозка кадра работает в iOS, Android и web.

## Вне рамок

3D-модели кабелей, несколько эталонов на плату, ручная калибровка по углам, ML-распознавание, автоопределение «другой платы», телеметрия, сохранение и шаринг замороженных кадров.

## Открытые вопросы

- Компиляция `.mind` в CI: офлайн-компилятор MindAR под Node или коммит заранее скомпилированного файла.
- Запуск `arcoreimg` в CI вместо ручной проверки.
