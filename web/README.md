# ConnectAR — Web (GitHub Pages)

Статическая версия без сборщика: ES-модули, [MindAR](https://github.com/hiukim/mind-ar-js) + three.js с CDN (грузятся только при открытии камеры), данные — из [`../shared_boards`](../shared_boards). Реализует [дизайн AR-распознавания](../docs/design-doc.md).

- **Сборка** — опрос «Ваша сборка» (память, накопители, видеокарта, вентиляторы, тип БП), чек-лист полной сборки по этапам, экран инструкции с пошаговыми действиями, предупреждениями и блоком «Со стороны блока питания». Шаги с `requires` заблокированы, пока не выполнено нужное («Сначала: …»); снятие отметки снимает и зависимые после подтверждения. Ответы и прогресс хранятся в `localStorage`.
- **Камера** — AR по эталону платы: подсветки разъёмов (three.js) и HTML-метки поверх видео; текущий шаг ярче, выполненные приглушены, разъёмы заблокированных шагов не показываются. Подписи раскладываются без наложений (сдвиг с выноской), одинаковые прямоугольники склеиваются («SATA3 0 / SATA3 1»). Фонарик — где камера его поддерживает. «Заморозить» — снимок кадра, дальше зум и тапы как на фото.
- **Фото** — запасной путь при любой ошибке (нет эталона, нет доступа к камере, браузер без WebGL, долгий поиск): снимок или фото из галереи, плата на нём ищется автоматически (MindAR по тому же `targets.mind`); не нашлась — пользователь ставит 4 угла платы. Любой снимок хранит гомографию «мм платы → снимок», поэтому метки на нём всегда соответствуют текущему опросу и прогрессу.

```
src/
├── app.js          # вкладки, чек-лист, экран инструкции
├── plan.js         # план сборки: board.json + ответы опроса → шаги (правила — shared_boards/README.md)
├── session.js      # сессия сборки (ответы опроса, план, выполненные шаги)
├── layout.js       # BoardLayout: rectMm → координаты якоря
├── markers.js      # состояния шагов и меток (current/pending/locked/done), склейка, раскладка подписей, тапы
├── homography.js   # гомография: DLT с нормализацией Хартли, RANSAC, проверка четырёхугольника углов
├── ar.js           # Tracker + Highlight + Labels на MindAR, снимок кадра, фонарик
├── photo-recognition.js # плата на фото: Controller MindAR, пары точек матчера → гомография
├── camera.js       # вкладка «Камера»: состояния, ошибки, таймеры, заморозка, фото и 4 угла
├── leaders.js      # выноски к сдвинутым подписям
└── photo-view.js   # BoardPhotoView(image, markers): зум, перемещение, тапы, ручки углов
```

## Локальный запуск

Нужен HTTP-сервер из корня репозитория (камера требует `localhost` или HTTPS):

```sh
npx serve .        # затем открыть http://localhost:3000/web/
```

AR включается, если у платы в `board.json` есть `target` и рядом лежит скомпилированный `targets.mind`:

```sh
cd web && npm ci
npm run compile-targets   # target.jpg → shared_boards/boards/<id>/targets.mind (в git не коммитится)
```

## Тесты

```sh
cd web && npm test        # Vitest: общие фикстуры BoardLayout и плана, логика меток, гомография, сессия
npm run test:e2e          # Playwright: распознавание фото, EXIF, память TF.js, чек-лист, заморозка
```

E2E генерируют сцены из `target.jpg` с известной гомографией и кадр фейковой камеры (`e2e/.scenes`, нужен пакет `canvas`) и подменяют CDN локальными three и MindAR. Нужен `targets.mind` (`npm run compile-targets`). В CI браузер ставится `npx playwright install --with-deps chromium`; локально можно взять системный: `CHROMIUM_PATH=$(which chromium) npm run test:e2e`. Фонарик в headless не проверить — только руками на Android и iPhone.

## Публикация

Workflow `.github/workflows/web.yml`: job `unit` — валидация `shared_boards` → `npm test` → сборка `_site` из `web/` и `shared_boards/` → компиляция `targets.mind` офлайн-компилятором MindAR под Node; job `e2e` — браузерные тесты; деплой на GitHub Pages после обоих. В настройках репозитория: Settings → Pages → Source: **GitHub Actions**.
